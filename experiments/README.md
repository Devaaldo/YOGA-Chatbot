# Experiments — model history

The production chatbot in `src/` and `api/` uses **one** model: the 12-class
semantic SVM trained by `notebooks/training_pipeline.ipynb`. This folder keeps
the earlier training tracks that produced the chatbot, so the notebooks and
reported numbers stay with the repo instead of living in separate repositories.

Four stages, in order:

| Stage | Folder | What it did | Headline result |
| --- | --- | --- | --- |
| 1 | `legacy-v3/` | First pipeline: 5 then 10 intents, TF-IDF + linear SVM | no recorded metric (notebooks were exploratory) |
| 2 | `model-comparison/` | Compared SVM, logistic regression and naive Bayes on the same data | notebook compares three models; the pickle found here is an MLP (see its README) |
| 3 | `svm-88class/` | 88 intents, one per kecamatan: pattern acquisition, preprocessing, TF-IDF, SVM, binary greeting detector, hybrid evaluation | **97.33%** test accuracy, 0.974 macro F1 (450 test samples) |
| 4 | `lstm-88class/` | Same 88 intents, Bidirectional LSTM on Word2Vec sequences | **96.35%** test accuracy (985 test samples) |

## Read the numbers with care

These figures come from **different datasets and different splits**, so they are
not a ranking:

- SVM 88-class: 1,797 train / 450 test.
- LSTM 88-class: 3,936 train / 985 test (augmented set).
- A later LSTM run with 5-fold CV on the smaller set scored **39.56%**; that
  collapse is what pushed the redesign, not the 96% run. Details and files in
  `lstm-88class/notes/`.
- Production (12 classes + entity extraction): 94.59% on 499 held-out samples.
  Fewer classes, a different task, so its number is not comparable to the 88-class
  runs either.

The 88-class setup also had 88 labels with roughly 25 examples each, which is why
greeting intents collapsed to 0.00 F1 in the low-performance analysis
(`svm-88class/notes/MANY_CLASSES_PROBLEM.md`). The current design replaced those
labels with 12 semantic intents plus an entity extractor for locations.

## Running the notebooks

Each track is self-contained with the folder layout its notebooks expect
(`notebooks/` reads `../data` and writes `../models`). Run them in order:

**SVM track** (`svm-88class/notebooks/`)
1. `01_Pattern_Acquisition.ipynb`
2. `02_Preprocessing.ipynb`
3. `03_Feature_Extraction.ipynb`
4. `04_SVM_Modeling.ipynb` and `04_Binary_GreetingDetector.ipynb`
5. `05_Evaluation.ipynb`, `05_Hybrid_Evaluation.ipynb`

**LSTM track** (`lstm-88class/notebooks/`)
1. `01_Pattern_Acquisition.ipynb`
2. `02_Preprocessing.ipynb`
3. `03_Feature_Extraction.ipynb` — writes `X.npy`, `y.npy`, `word2vec.model`
4. `04_LSTM_Modeling.ipynb` — needs TensorFlow 2.x
5. `05_Evaluation.ipynb`

Intermediate files (`X.npy`, `y.npy`, `preprocessed_text.csv`, `word2vec.model`)
are generated by steps 2–3 and are intentionally not committed. The committed
`models/` snapshots are the ones the reported numbers came from.

Extra packages the notebooks need are listed in
[`requirements.txt`](requirements.txt) here (`gensim` for the LSTM track,
`tensorflow-cpu` if you want to load or retrain the LSTM). They are not part of
the app's runtime requirements.

## What is preserved and what is not

- **LSTM model**: `lstm-88class/models/yoga_lstm_best.h5` (5.0 MB, valid HDF5,
  412,824 parameters, matches its `model_info.json`).
- **SVM 88-class model**: the pickle was never committed to the old repositories,
  so only metrics and plots survive. Retrain it with `04_SVM_Modeling.ipynb`.
- **Production SVM**: `models/*.pkl` at the repository root, loaded by the API.
- **Old repositories**: `Devaaldo/yoga-v3`, `Devaaldo/yoga-v2`,
  `Devaaldo/YOGA-Chatbot-PRIVATE`. Their code is superseded by `src/` and `api/`;
  only notebooks, artifacts and diagnostic notes were carried over.
